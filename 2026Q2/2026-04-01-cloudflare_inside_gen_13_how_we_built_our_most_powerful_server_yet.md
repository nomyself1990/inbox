# Inside Gen 13: how we built our most powerful server yet

- **来源:** https://blog.cloudflare.com/gen13-config/
- **作者:** Syona Sarma、JQ Lau、Ma Xiong、Victor Hwang
- **日期:** 2026-03-23
- **出处:** Cloudflare Blog
---

## 概览
这篇文章讲的是 Cloudflare 最新一代通用服务器 **Gen 13** 的硬件设计思路：在 FL2（Rust 重写的核心请求处理层）上线后，软件栈对硬件能力的利用方式也变了，于是他们顺手把服务器平台一起升级。

一句话总结：**这是一次围绕吞吐、能效、带宽、内存容量和未来扩展能力做的整机重构，而不只是简单换颗更强的 CPU。**

## 核心规格
Gen 13 的关键配置：

- **CPU:** AMD EPYC 9965 Turin，192 核
- **内存:** 768 GB DDR5-6400
- **存储:** 24 TB PCIe 5.0 NVMe（3 x 7.68 TB E1.S）
- **网络:** 双口 100 GbE
- **形态:** 2U1N，单路

对比上一代 Gen 12：

- 核心数翻倍：96 → 192
- 内存容量翻倍：384 GB → 768 GB
- 存储容量提升 1.5 倍：2 盘 → 3 盘
- 网络带宽提升 4 倍：双 25 GbE → 双 100 GbE
- 电源提升：800W → 1300W Titanium

## 他们声称带来的收益
文中给的结果很直接：

- **吞吐最高可到 Gen 12 的 2 倍**，同时仍满足延迟 SLA
- **性能 / 瓦提升最高 50%**，降低机房扩容成本
- **单位机架吞吐最高提升 60%**，在机架功耗预算不变的前提下更划算
- 新增 **PCIe 加密硬件支持**，并继续支持内存加密
- 对高功耗 PCIe 加速卡有更好的散热与供电支撑

## 我觉得值得记的点

### 1. 这不是“堆料”，而是按 Cloudflare 工作负载重选平衡点
Cloudflare 没有选双路，而是继续坚持 **单路 2U1N**。这通常意味着他们更看重：

- NUMA 复杂度更低
- 一致性更好
- 平台运维更简单
- 单机性能已足够高，没必要为双路付出额外复杂度

### 2. Turin Dense 192 核，明显是在赌高并发吞吐而不是超大缓存
上一代用的是 Genoa-X，96 核但 L3 cache 很大；这一代换成 Turin Dense 192 核，L3 cache 反而小很多。这个选择很说明问题：

- Cloudflare 当前主负载更适合 **更多核心 + 更高总体吞吐**
- FL2 之后的软件栈可能更能吃下高并发并行能力
- 对他们来说，**单位功耗吞吐** 比“单核 / 大缓存极限表现”更重要

### 3. 网络带宽从 25G 直接跳到 100G，很像是在为后续几年留余量
双 100 GbE 是这代里一个非常激进但合理的升级。对边缘网络来说，CPU 变强如果 NIC 跟不上，很容易把瓶颈挪到 I/O 上。4 倍带宽意味着：

- 单机吞吐更容易真正释放出来
- 机架级部署密度可以提高
- 以后接更重的服务、缓存、加速或安全工作负载时不容易卡网卡

### 4. 他们开始强调“未来 PCIe 加速器支持”，这点很有意思
文中提到 Gen 13 对更热、更耗电的 drop-in PCIe accelerators 支持更好。这通常不只是机械设计优化，而是在暗示：

- 平台开始认真考虑更强的 SmartNIC / DPU / 加速卡 / AI 类扩展卡
- 服务器底板、供电、散热、空间布局都在为未来能力预留

### 5. 把安全能力做到硬件层，属于 Cloudflare 的正常风格
除了内存加密，这代还强调 **PCIe encryption hardware support**。这说明他们在做的不是“功能上线即可”，而是把整个数据路径的基础安全能力往底层推进。

## 一句话总结
**Gen 13 的本质，不是“换了更猛的服务器”，而是 Cloudflare 针对 FL2 时代网络负载，把 CPU、内存、存储、带宽、功耗和未来加速器支持重新做了一次系统级平衡。**
